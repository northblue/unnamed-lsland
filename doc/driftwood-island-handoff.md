## 1. 用户目标与已确定方向

- 项目名：Driftwood Island，中文名漂木岛，仓库名 driftwood-island。
- 做一个网页版岛屿生存、探索与建造游戏，主要用于学习，也给自己的两个儿子玩。
- 将来可能发布到 GitHub，帮助其他学习者减少摸索成本；目前不以商业化为目标。
- 使用 Three.js，先用程序生成的简单多边形和几何体制作原型，优先打通 gameplay flow。
- 后期再引入 Blender 或免费模型素材改善外观，不让建模成为启动门槛。
- 外部素材希望免费、许可清楚，适合未来公开项目；优先考虑 CC0。
- 用户使用 MacBook 上的 Codex 开发，在 ChatGPT 中讨论想法，希望通过仓库文档延续上下文。

## 4. 讨论过但尚未最终确认的建议

以下为助手建议，可作为默认方案讨论，不能表述为用户已经确认：

## 5. 原型实现原则

先用简单形状：角色用胶囊/方块，树用圆柱和圆锥，石头用多面体，小屋用盒子和简单屋顶，海水用蓝色平面。

游戏状态、碰撞与视觉表现分离。例如树有稳定 ID、位置、资源状态和简单碰撞范围；圆锥树冠只是显示方式。以后替换模型时，应尽量保留资源规则、交互与存档。

- 统一尺寸单位、模型朝向和原点位置；树和建筑的原点位于地面接触处。
- 存档保存必要的游戏数据，不直接序列化 Three.js 场景对象。
- 初期只做必要模块，不为可能的多人、复杂物理或 ECS 提前构建庞大框架。
- 每一阶段均保留可运行、可试玩版本。
- 实现后说明改动、运行方式和验证结果，帮助用户学习。

## 6. 建议里程碑与验收

### M1：小岛与移动

- 建立最小开发环境，页面能运行。
- 显示简单小岛、海面、树和石头；颜色协调，基本光照与阴影。
- 一个占位角色能通过 WASD/方向键移动。
- 镜头从斜上方观察，移动方向与画面直觉一致。
- 角色不能穿过主要障碍或走出可行走区域。
- 窗口尺寸变化后画面正常；页面显示操作说明。

验收：用户能启动项目，在小岛上自由走动，没有明显穿模或控制台错误。此阶段不要求背包、建造或复杂水面。

### M2：采集

- 接近资源后有明确提示，通过一个交互键采集。
- 资源数量和场景状态同步更新，不能无限重复领取已耗尽资源。
- 加入简单反馈，例如物体晃动、文字提示。

### M3：建造循环

- 实现一种建筑即可，例如小屋。
- 放置前显示预览，区分合法与非法位置。
- 材料不足时有提示；成功放置只扣除一次材料。
- 禁止放到水中或与主要障碍重叠。

### M4：保存与试玩

- 本地保存资源、建筑和必要世界状态，并包含存档版本号。
- 刷新后恢复；提供有确认步骤的重置功能。
- 让孩子试玩，根据实际反馈调整操作和节奏。

### M5：外观升级与开源整理

- 逐步替换几何体为模型，改善海水、灯光和动画。
- README 包含启动步骤、操作说明、截图、学习路线和已知限制。
- 保留可运行阶段的 Git 标签。
- 项目代码许可证由用户选择；每项外部素材独立记录来源与许可，不默认与代码同许可。
